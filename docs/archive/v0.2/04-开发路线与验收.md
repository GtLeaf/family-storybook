# 开发路线与验收

版本：v0.2｜日期：2026-10-19｜性质：建议执行路线，尚未启动开发

## 1. 实现取向

先做一个以 360×360 圆形有效区域为基准、可在浏览器完整体验的章节，再迁移到 ESP32 单点触摸设备。网页与固件分别实现渲染，不把网页直接视为设备固件。叙事页用配置描述，程序复用寻找、选择、摆放三个组件；避免每一页各写一套逻辑。

首版不依赖后端：故事、图片和音频随网页提供，进度保存于本机。网页没有账号，不请求儿童姓名、照片、生日、麦克风或位置。测试反馈由家长在设备外提供；也不接入第三方行为追踪脚本。

运行时无需大模型。后续可使用 AI 辅助草拟内部素材和文案，所有输出均需内容与权利审核；不会因此默认增加儿童 AI 聊天入口。

## 2. 建议模块

| 模块 | 职责 | 重点 |
|---|---|---|
| 书架与导航 | 开始、继续、重玩、日记、家长页 | 重玩确认、退出保留进度 |
| 故事播放器 | 按配置推进 S01—S09 | 合流分支、手动继续、避免重复触发 |
| 寻找组件 | 热点、收集、提示层级 | 幂等收集，不重复计算 |
| 选择组件 | 试听、确认、分支播放 | 试听与确认分离 |
| 摆放组件 | 固定任务与创意布置 | 选槽位再确认、固定布局、无拖动依赖 |
| 声音管理 | 旁白、角色、环境与暂停 | 语音互斥、切后台暂停 |
| 存档管理 | 校验、版本迁移、损坏回退 | 内存及时更新，设备按检查点落盘 |
| 素材加载 | 当前场景优先、后续预取 | 缺失时可恢复，不出现死页 |
| 日记展示 | 显示本次实际布局 | 使用同一布局数据，避免截图依赖 |

具体框架、依赖版本和部署方式在立项后选择并核对官方文档；本方案不把某个库写成已采用事实。轻量组件式前端即可满足首章，无需先引入完整 3D 游戏引擎。

## 3. 内容数据与存档草案

故事配置包括：章节 ID、节点 ID、场景资产、旁白切片、可用交互、完成条件、下一节点与可选书签。状态变化由组件提交，播放器判断是否允许推进。

存档建议包含：

| 字段 | 作用 |
|---|---|
| schemaVersion / storyVersion | 区分存档结构和故事内容版本 |
| chapterId / nodeId | 当前章节、逻辑节点与短句编号 |
| collectedItemIds | 已收集的 3 件物品 ID |
| companionChoice | 已确认的陪伴选项 |
| stonePlacements | 石头 ID 与目标位置 ID 的映射 |
| picnicLayout | 5 件物品与兼容槽位 ID 的映射及是否已放置，不存浏览器坐标 |
| handledBookmarkIds | 本轮已处理的亲子书签 |
| completed | 是否已经完成本章 |
| audioPreferences | 音量与旁白偏好 |

不存原始触摸轨迹或逐次点击日志。存档只写有限字段并校验范围；网页适配本机存储，设备适配有版本与校验的检查点存储。ESP32 内存状态即时更新，Flash 写入合并在节点切换、明确退出、休眠前等检查点；突发断电允许回退至最后成功提交点。遇到未知物品、无效节点或结构损坏，回退到最近可恢复节点。无法安全恢复时先说明情况，再由用户选择重新开始；不静默抹掉已有布局。

## 4. 首版验收标准

所有阈值均为项目验收目标，不是已测得的表现。

| 编号 | 用户可见结果 | 可执行验收 |
|---|---|---|
| R01 | 能完整玩完 | 从清空记录开始，S01—S09 无死路，最终出现与实际摆放一致的日记 |
| R02 | 不认字也能理解主要操作 | 开启旁白后，3 类玩法都有语音与视觉示范；亲子试用记录是否需要额外解释 |
| R03 | 有稳定的寻找规则 | 以不同顺序收集 3 件物品均能推进；重复点击不重复收集 |
| R04 | 两条对话都成立 | A/B 分别产生对应台词，均合流至 S06；无好坏评分 |
| R05 | 不会拖动也能完成 | 全章只用点击／触摸点选即可完成；桌面可用键盘激活同等操作 |
| R06 | 任务摆放容错 | 任意顺序放石头均成功；放错只撤销本次，点到无效位置不丢道具，确认前可更换选择 |
| R07 | 槽位布局能保存 | 3 份餐具落位才出现完成按钮；装饰可跳过；恢复后位置合理 |
| R08 | 家长参与可选 | 两个亲子邀请均能讨论或立即继续，均不影响完成；讨论期间不催促 |
| R09 | 可以中途停止 | 网页操作后刷新可恢复；设备退出／休眠后恢复已提交快照，突然断电不损坏旧快照；后台／息屏不继续播放 |
| R10 | 声音可控 | 语音不叠加；静音可玩；音频失败不会卡住故事 |
| R11 | 设备适配可用 | 360×360 圆形裁切与 12 px 径向安全边距下，全部目标、文字和按钮完整可用；再验证网页宿主设备 |
| R12 | 本机数据可管理 | 家长侧能查看说明并清除存档；清除后可从新故事开始 |
| R13 | 素材来源可追踪 | 每项正式资源有权利信息及来源记录，临时资源有显式标记 |
| R14 | 结束清楚 | 完成后可回书架，不自动开始新章节，没有连玩刺激或付费打断 |
| R15 | 单点触摸完成全章 | 关闭拖动、滑动、悬停、长按后仍可完整体验；弹层关闭的同一触摸不穿透到背景 |
| R16 | 真机大小可用 | 目标按实体屏幕尺寸检查，儿童无需用指甲找小点；若不可用先减少同屏内容 |
| R17 | 圆屏短句可读 | 操作页最多 1 行 10 字；阅读页每行最多 9 字、最多 2 行；长文逐句查看，不滚动 |

## 5. 推荐阶段与工作量

以下是小体量首章、三角色有限动作、无后台的初步估算，不是报价。按 1 名熟练前端开发、1 名可兼职配合的美术／策划、可安排录音资源来估计。

| 阶段 | 可评审成果 | 估计投入 | 离开该阶段的条件 |
|---|---|---|---|
| A · 内容与角色方向 | 确认脚本、角色轮廓、素材台账 | 2—3 人日 | 剧情、工作名使用范围和视觉方向清楚 |
| B · 灰盒全流程 | 占位图下可玩完整一章 | 4—6 人日 | 寻找、两条分支、两模式点选摆放和结束均在圆形画布贯通 |
| C · 正式内容与表现 | 三场景、三角色、旁白和界面 | 6—10 人日 | 正式素材可读、播放正常、适配主要设备 |
| D · 恢复与亲子打磨 | 存档、异常恢复、试用和修订 | 3—5 人日 | R01—R17 在网页层检查完成，主要试用问题处理 |
| 合计 | 一章可评审网页原型 | 15—24 人日 | 不含 ESP32 移植、硬件联调、法务、发行申请与新增章节 |

人日是全部参与者的工作量之和，不等于自然日。两人部分并行时，日历时间先按约 3—5 周预留，再根据美术与录音供应调整。当前未作正式工期承诺。加入圆屏约束后需在灰盒阶段重新校准网页估算；设备移植另估，先完成芯片／显示／触摸／音频／存储实测，不能把原网页估算当成固件交付时间。

现金预算按“开发与策划人日 × 对应费率 + 美术与录音委托 + 版权核查／发行支出 + 约 20% 预留”估算。因人力和素材来源未定，暂不给出虚构的总报价。

## 7. 测试范围

自动检查优先覆盖会造成实际损失或卡关的逻辑：集齐条件、分支合流、目标占用、圆屏热点边界、短句长度、存档有效性和错误恢复。不为每句固定台词分别编写测试。

人工走查至少覆盖：两条对话路线；3 种寻找顺序；单点选择与确认、误触和跨页面抬手；S02、S05、S06、S07 中断恢复；静音与音频不可用；手机旋转；存储不可用；重复进入与清除进度。

首要基线为 360×360 圆屏与实际物理尺寸；网页宿主再覆盖 iPhone Safari、Android Chrome、iPad Safari 及桌面主流浏览器中的代表设备。正式确定版本号前核对实际试用设备，不在方案阶段承诺“兼容全部手机”。

网页性能目标：静态图片和分段语音优先，避免自动播放视频；当前场景优先加载，后续预取。先把可交互首屏压到约 3 MB 内、单章传输资源压到约 15 MB 内作为资产预算，最终以画质、音频长度和真实网络测试调整。加载超时提供重试与可读说明，不能白屏等待。上述 MB 是网页传输预算，不是固件内存或 Flash 预算；设备资源账与缓冲计算见 [ESP32 圆屏迁移与交互约束](06-ESP32圆屏迁移与交互约束.md)。

## 8. 亲子试用

必须在预览网页 1:1 和实际设备上分别试用；不能仅用电脑上的放大圆形画面验收。建议邀请 6—8 组家庭做探索性试用，覆盖 4—5 岁与 6—7 岁；这只能发现可用性问题，不能证明教育效果或市场需求。

每次先由家长阅读说明。观察者不替孩子解释规则，只在卡住或家长请求时介入。默认不录音录像，由家长同意后做简短观察记录，不记录儿童真实姓名。

| 观察问题 | 记录方式 | 第一轮参考目标 |
|---|---|---|
| 能否完成一章 | 是否完成、卡在哪页 | 至少约 80% 家庭无需制作人员接手操作 |
| 能否理解动作 | 首次操作前额外解释次数 | 找出所有需要反复口头解释的界面并修订 |
| 家长是否自然加入 | 两次邀请中实际交流情况与反馈 | 多数家庭愿意交流至少一次；跳过者原因可解释 |
| 时长是否合适 | 开始到结束的粗略时长 | 多数落在约 10—15 分钟，超时需分辨聊天或卡关 |
| 是否愿意再体验 | 结束后询问家长和孩子 | 收集原因，不用奖励诱导“愿意” |

样本太小时不机械依赖百分比；“大多数家庭顺利、少数问题可定位”比漂亮数字更重要。任何导致无法继续、进度丢失或误触不断的问题，都优先于新增章节处理。

## 9. 发布决策

灰盒试玩、带正式素材的家庭试用、公开商业发行是不同阶段。到公开发行时，另行按实际地区、渠道、产品性质和数据处理确认资质、内容、隐私及平台要求；本方案不假设“做成 H5 就免除相关要求”。

先交付可评审原型，再基于反馈决定是否立项做系列、是否使用维尼角色以及是否投入正式发行。
