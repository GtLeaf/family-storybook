# 产品方案：一起的小冒险

版本：v0.3｜2026-10-19｜手机 Web 优先

## 1. 产品定位与验证目标

给 4—7 岁孩子和家长的一本可玩的森林故事书。打开链接，听一小段故事，用寻找、选择和布置参与其中，最后留下一页属于自己的野餐日记。

第一阶段交付可以独立使用的手机 Web；第二阶段验证家庭是否持续需要内容；第三阶段才根据硬件需求验证结果推进 ESP32。Web 不使用 360×360 圆形裁切，不以圆屏真机验收作为首版阻塞条件。

首章沿用《风吹走的野餐》及原有原著角色的新写支线。产品显示名采用“一起的小冒险”，角色与发行边界继续参考 05 文档。插画为原创布偶方向的 AI 辅助原型素材，发布前仍需权利和人工内容复核。

## 2. 用户与使用方式

- 核心用户：4—7 岁儿童和共同参与的家长；优先验证 4—5 岁共玩，再观察 6—7 岁自主性需求。
- 使用情境：家庭在白天或晚间有一小段共同时间，通过手机链接打开；无需账号或安装。
- 听故事：自然段内语音连续播放，到互动或邀请处等待，不自动替孩子完成任务。
- 家长读：关闭自动朗读，保留完整文字，手动推进。
- 时长：观察实际游玩和聊天时间；约 5—10 分钟故事与操作、加上自愿交流，不靠翻页次数凑时长。

## 3. 首章闭环

风吹散用品 → 找回三件物品 → 一起观察风的痕迹 → 邀请担心风的朋友 → 选择倾听或陪伴 → 一起固定野餐垫 → 选择朋友的座位与装饰 → 开餐 → 留下日记与可选离屏活动。

没有输赢、计时器、道德评分或强制打卡。屹耳可以保持安静，不需要通过任务被“治愈”。

## 4. 手机交互原则

1. 插画优先：竖屏大画面，字幕与主操作在画面之外，手机空间用于故事表达。
2. 简单动作立即反馈：点击可见线索找物品；点击空垫角落下石头；重复点击不重复计数。
3. 对话保留试听与独立确认，避免点错即推进；两种选择都通向完整结局。
4. 餐具选择座位后直接放置；可点已放置餐具、再点另一位置交换，允许自由调整。
5. 装饰入口直接可见，餐具齐全即可开餐；纸花、叶片不作为过关条件。
6. 找齐物品后再邀请讨论，避免第一次发现就被打断；随时继续，不记录回答。
7. 一个主动作与少量明确次动作；不把“只能一个按钮”当作全局限制。
8. 不依赖拖动，键盘可操作全部关键控件；保留暂停、重听、文字与减少动态效果。

## 5. 首版范围

P0：单章完整故事、3 类交互、两条对白分支、两次邀请、语音/家长读模式、暂停和返回、每次有效操作后本地存档、日记与重摆、设置和明确清除确认、素材加载失败重试、存储不可用降级。

语音原型使用设备提供的中文朗读能力；没有可用中文声音或播放失败时明确提示，切为家长朗读。正式内容市场试用前应评估是否替换为统一录制音频，避免不同设备声音质量影响结果。

后置：账户、支付、联网同步、实时 AI、录音识别、儿童上传、复杂日记导出、圆屏预览、固件实现。首版不默认收集行为数据；通过家长回访验证，不加入隐形埋点。

## 6. 市场验证

阶段一：6—8 组家庭的观察试用，记录是否完成、卡关位置、需要解释的操作、家长是否愿意加入。样本用于发现问题，不用于宣称市场成功。

阶段二：修复阻塞后交给家庭独立使用，约一周后回访。分别询问是否重新打开本章、是否想体验新故事、实际使用场景、与现有绘本相比的价值。区分旧章重玩和新章需求，不将使用时长最大化作为目标。

阶段三：用一篇更短的新故事测试持续内容需求；明确故事包内容和价格，再观察真实选择。具备发行条件后才测试实际购买，不以“愿意付费吗”的口头肯定代替支付验证。

是否进入硬件阶段另行验证：家长是否需要不用手机的独立设备，孩子能否独立使用，设备尺寸、价格和内容更新是否可接受。Web 内容成立不等于硬件成立。
